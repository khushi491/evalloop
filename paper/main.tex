\section{Method}
\begin{itemize}
  \item \todo{Khushi writes}
  \item Roles: runner, judge, patcher. Self-refine adds a reviser and does not store a policy.
  \item Hard checks: in-process, not pasted into the judge prompt
  \item Patcher feedback switch: critique-only / hard-checks-only / both
  \item Stopping switch: judge-only / judge + hard checks
  \item Held-out: frozen learned policy, no further patching (policy method only)
  \item Pointer: \texttt{src/lib/improvement-loop.ts}, \texttt{src/lib/eval/suite.ts}
\end{itemize}

\section{Limitations}
\begin{itemize}
  \item \todo{Khushi writes}
  \item Free-compute constraint: small model, small task set, few seeds
  \item Gemini planning assumption is about 20 calls/day. Not a measured quota. See \texttt{docs/EXPERIMENTS.md}.
  \item One judge model family. Judge and generator can share a provider.
  \item Hard checks are narrow (words, keywords, JSON, regex samples). They can miss failures the judge names, and the reverse.
  \item Best-of-$n$ selection uses the same judge the study is worried about.
  \item No human rating in this design.
\end{itemize}
